# knowledge-rag-1c

> **1C:Enterprise (BSL + MDO) Parser Extension for [lyonzin/knowledge-rag](https://github.com/lyonzin/knowledge-rag)**
>
> Дополнение к локальному гибридному RAG MCP-серверу `knowledge-rag` для глубокого семантического поиска по коду 1C:Предприятие (модули `.bsl`), встроенным запросам 1С и метаданным проектов 1C:EDT (`.mdo`).

---

## 🎯 Зачем это нужно

При разработке крупных конфигураций 1C:Enterprise (EDT):
* `MCP-EDT` незаменим для точных синтаксических операций: AST, валидация строгой типизации (`//@strict-types`), переходы к определениям и проверка ошибок компиляции.
* **`knowledge-rag` с расширением `1C`** решает задачу **семантического поиска прецедентов, шаблонов и алгоритмов**, когда точное имя метода или объекта заранее неизвестно (например: *«Как в проекте работают с кэшем ИнтеграцияПУ и читают xlsx?»*, *«В каком регистре хранятся остатки паев и как к нему пишут запросы с границей Включая?»*, *«Где проверяется статус обмена с внешней системой?»*).

## ✨ Возможности

### 1. Парсер модулей 1С (`.bsl`):
* **Определение контекста метаданных по пути EDT:**
  * `.../Documents/<Имя>/ObjectModule.bsl` → `Документ.<Имя> (МодульОбъекта)`
  * `.../Documents/<Имя>/ManagerModule.bsl` → `Документ.<Имя> (МодульМенеджера)`
  * `.../Documents/<Имя>/Forms/<Форма>/Module.bsl` → `Документ.<Имя>.Форма.<Форма> (МодульФормы)`
  * `.../CommonModules/<Имя>/Module.bsl` → `ОбщийМодуль.<Имя>`
  * `.../AccumulationRegisters/<Имя>/RecordSetModule.bsl` → `РегистрНакопления.<Имя> (МодульНабораЗаписей)`
  * `.../InformationRegisters/<Имя>/ManagerModule.bsl` → `РегистрСведений.<Имя> (МодульМенеджера)`
  * (и аналогично для Catalogs, Reports, DataProcessors, BusinessProcesses и др.).
* **Контекстные заголовки (Context Headers):**
  Каждый чанк содержит синтетическую шапку:
  ```bsl
  // [1С BSL] Объект: Документ.РасчетДанныхДляВнешнихСистем (МодульМенеджера)
  // Область: ПрограммныйИнтерфейс | Метод: РассчитатьСтоимостьАктивов (Экспорт)
  // Запросы к таблицам: РегистрНакопления.ОстаткиПаев.Остатки
  //
  ```
* **Семантическая нарезка по методам:**
  * Код режется строго по границам `Процедура` / `Функция` ... `КонецПроцедуры` / `КонецФункции`.
  * Захватываются предшествующие аннотации (`//@strict-types`), описания параметров (`// Параметры:`) и директивы компиляции (`&НаСервере`, `&НаКлиенте`).
  * Отслеживаются области препроцессора (`#Область` ... `#КонецОбласти`).
  * Для длинных методов (> 2500 символов) выполняется интеллектуальное секционирование с сохранением шапки `[Часть X/Y]`.
* **Очистка и извлечение запросов 1С:**
  * Удаляются лидирующие символы переноса строк запросов `^\s*\|`, очищая текст для векторной модели (`multilingual-e5-large` / `bge-m3`).
  * Регулярными выражениями извлекаются обращения к таблицам 1С после `ИЗ` и `СОЕДИНЕНИЕ` (например, `РегистрНакопления.ОстаткиПаев.Остатки`) и сохраняются в метаданных `metadata["query_tables"]`.

### 2. Парсер метаданных 1С EDT (`.mdo`):
* XML-парсинг определений метаданных EDT (`AccumulationRegister`, `Document`, `Catalog`, `InformationRegister`, `CommonModule` и др.).
* Извлечение измерений (`dimensions`), ресурсов (`resources`), реквизитов (`attributes`) и табличных частей с типами данных и флагами.
* **Индексация комментариев и подсказок (`toolTip`):**
  В проектах 1С в `toolTip` часто заложены важнейшие архитектурные правила и алгоритмические ограничения — они полностью извлекаются и индексируются.
* Автоматическая генерация структурированного Markdown-паспорта объекта с умным разбиением по разделам.

## 🚀 Быстрый старт (Установка)

### 1. Установка в активное окружение `knowledge-rag`
Клонируйте репозиторий и запустите скрипт наката патча:
```bash
git clone https://github.com/VVi3ard/knowledge-rag-1c.git
cd knowledge-rag-1c
python apply_patch.py
```
*(Скрипт автоматически найдет пакет `mcp_server` в активном Python/venv, скопирует `parsers_1c.py` и аккуратно зарегистрирует обработчики в `config.py` и `ingestion.py`).*

Либо укажите путь к `mcp_server` явно:
```bash
python apply_patch.py --target /path/to/site-packages/mcp_server
```

### 2. Прогон тестов
```bash
python -m unittest discover
```

### 3. Настройка `config.yaml`
Добавьте поддержку форматов `.bsl` и `.mdo` в конфигурационный файл `knowledge-rag`:
```yaml
documents:
  supported_formats:
    - .md
    - .markdown
    - .bsl
    - .mdo

  exclude_patterns:
    - "CI/**"
    - "live-client/**"
    - "xUnitForEDT/**"
    - "ИнструментыБСП/**"
    - "ClientsFiles/**"
    - ".git/**"
    - ".ai-artifacts/**"
    - "Configuration/.settings/**"

  chunking:
    chunk_size: 1800
    chunk_overlap: 200

models:
  embedding:
    profile: "multilingual" # intfloat/multilingual-e5-large (1024 dims)
    gpu: "true"

  reranker:
    enabled: true
    model: "jinaai/jina-reranker-v2-base-multilingual"
```
